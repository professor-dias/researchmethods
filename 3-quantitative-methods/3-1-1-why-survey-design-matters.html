Why Survey Design Matters for Analysis

Before we can analyze anything, we need to describe it. A variable is simply a property that varies from person to person, case to case. Let's see that happen live — with Pokémon.

Gotta catch 'em all

Let's catch some Pokémon! As the video plays, make a note of every Pokémon you catch (hear named). Who caught the most?

Reflective Questions
  • How many water-type Pokémon were there?
  • What was the 31st Pokémon named in the video?
  • How many were yellow in color?
Wouldn't it be nice if there was a system or workflow to capture data in a structured format so we could make some meaningful analysis? Thankfully, it does exist — in surveys and variables.

A Pokédex field survey

Map the questionnaire and rating scale to the table below — a dropdown, a rating scale, a yes/no, a number... every question is a variable waiting to happen.

Every column above is a different variable — but they clearly don't all behave the same way. Some are words, some are numbers, some have a natural order and some don't. That's exactly why counting "how many water-type" only worked once the data was structured this way. To pick the right chart or the right test, we first need to know exactly what kind of variable each column is. That's the rest of this topic.
