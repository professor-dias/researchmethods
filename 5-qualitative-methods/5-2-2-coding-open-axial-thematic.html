A Code Is a Label, Not a Summary

A code is a short label attached to a chunk of text that captures one idea it contains. "I just felt like nobody was really listening to me at the appointment" might get coded feeling-unheard. That's it — you're not summarizing the sentence, you're tagging the specific idea inside it, so you can later pull every instance of that idea back together across every transcript.

Coding is not the finish line. It's the raw material. The real analytic work happens next, when codes get organized into categories and then themes (5.2.4) — coding is where you make sure nothing gets lost along the way.

Three Passes, Each Doing Different Work

These aren't three competing methods to choose between — in grounded-theory-style coding, they're sequential stages of the same analysis, each one working on the output of the last.

Open Coding
Go line by line (or sentence by sentence) and label every distinct idea you see — broadly, without worrying yet about how codes relate to each other.
This pass is deliberately over-inclusive. You'll generate far more codes than you end up using — that's expected, not a mistake.
Axial Coding
Now look across your open codes and start connecting them — which ones are really the same idea in different words? Which ones seem to cause, or follow from, another?
Related codes get grouped into broader categories. This is where the dataset starts to show structure instead of just a long flat list.
Selective / Thematic Coding
Identify the core categories that the whole analysis actually revolves around, and code the rest of the data specifically in relation to those core ideas.
This is the pass that produces your final themes — see 5.2.4 for how categories become the themes you'll actually report.

Watch It Happen on One Quote

Code this sentence, pass by pass 

"Honestly, by the third appointment I stopped bringing up my side effects at all. What was the point — nobody wrote it down, nobody followed up. I just started managing it myself."

Open coding might tag several separate ideas inside this one quote: stopped-reporting-symptoms, perceived-clinician-inattention, self-management, repeated-negative-experience.

Axial coding notices that stopped-reporting-symptoms, perceived-clinician-inattention, and repeated-negative-experience are really pieces of one broader category: disengagement following unaddressed concerns. self-management gets grouped separately, under a category about patient-led coping.

Selective/thematic coding, after seeing this pattern echoed across a dozen other transcripts, elevates disengagement following unaddressed concerns to a full theme — and now every other transcript gets re-checked specifically for instances of it.

Where Do Your First Codes Come From?

Inductive Coding
Codes emerge directly from the data itself — you start with no predetermined list, and let the transcripts generate the categories.
Better suited to exploratory questions, and consistent with a constructivist or interpretivist paradigm (5.2.1).
Deductive Coding
You start with a codebook already built from theory or prior literature, and apply those existing codes to the new data.
Faster and more consistent across coders, but risks missing anything the existing framework didn't anticipate.

Most real projects land somewhere between the two: a small set of theory-driven starter codes, refined and expanded inductively as the data reveals things the starting framework didn't predict.
