Same Toolbox, Different Question

Program evaluation uses the same rigorous methods as research (Topics 2–5) — but the question it answers is different. Research asks "what's generally true?" Evaluation asks "is this specific program working, for these specific people, and how do we make it better?" The result isn't meant to generalize — it's meant to inform a decision.

Evaluation should start when a program is still an idea, not get bolted on after the fact. A helmet-subsidy program that skips formative evaluation might not discover until launch that riders find helmets too hot, too heavy, or simply inconvenient to carry — each one a fixable problem an early focus group would have surfaced.

The Logic Model: One Chain, Five Links

Almost every evaluation is organized around the same underlying chain, connecting what you put in to what ultimately changes.

→
Outputs
→

→

Inputs: Funding, staff, equipment, space, partnerships — what the program has to work with.
Activities: What actually happens — education sessions, materials distributed, outreach conducted.
Outputs: Countable proof the activities occurred — number of sessions held, number of people who attended.
Outcomes: Short- and medium-term change in the people reached — knowledge, attitudes, behavior.
Impact: The long-term goal the whole program exists for — typically a change in morbidity or mortality, and usually the hardest link to actually measure.

Process and outcome evaluation work together: process data tells you whether the program ran as intended, so that if outcome data shows no effect, you can tell "the program doesn't work" apart from "the program was never actually delivered properly" — two very different, and very differently actionable, conclusions.

Was It Worth What It Cost?

Five different cost questions, each answered by a different technique — open each one to see the logic.

Cost Analysis — can we afford it? 

Add up every resource the program consumes — staff time, materials, space, travel — over a defined period, then divide by clients served to get a cost per client.

Threshold Analysis — how few cases would we need to prevent to break even? 

Divide the program's total cost by the lifetime medical cost of treating one case of whatever it prevents. The result is the number of cases you'd need to prevent for the program to pay for itself. You often don't need to know the exact number of cases prevented — just whether your best estimate is plausibly above or below that number. A state HIV testing program, for example, might only need to prevent 5 infections to be cost-saving — a bar that's often easy to clear.

Cost-Effectiveness Analysis — which version of this program is the best value? 

Cost per case prevented, used to compare programs within the same disease area and prioritize funding toward the lowest cost-per-case options first.

Cost-Utility Analysis — how do we compare across completely different diseases? 

Uses cost per Quality-Adjusted Life-Year (QALY) — a year lived in perfect health = 1.0 QALY, adjusted downward for reduced quality of life. Because QALYs use one common unit, they let policymakers compare a diabetes program against an HIV program against a cancer-screening program on the same scale. A commonly cited (if debated) rule of thumb: under roughly $50,000 per QALY is considered cost-effective.

Worked Example: Pool Cool Sun-Safety Program

A CDC-funded program teaching sun safety at swimming pools shows all four evaluation types working together on one real project.

Formative: Focus groups and interviews with parents, children, and pool staff shaped a program grounded in Social Cognitive Theory — lifeguard training, sunscreen stations, shade structures, lessons woven into swim classes.
Process: Monitoring forms and observation logs confirmed lessons were actually delivered as designed — and caught that weather sometimes disrupted implementation, context worth knowing before judging outcomes.
Outcome: A randomized trial — 15 intervention pools vs. 13 control pools, pools as the unit of randomization rather than individuals — found real increases in sunscreen use, shade-seeking, and pool policy changes.
Result: A modest but genuine effect, strong enough that the program was later scaled up and disseminated nationally.
Notice the unit of randomization: entire pools, not individual swimmers. That's a design choice (2.2) made because the intervention itself operates at the pool level (staff training, signage, sunscreen stations) — individuals within the same pool aren't independent of each other, so they had to be randomized as a group.
